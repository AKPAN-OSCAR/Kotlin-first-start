# How this path works

## Introduction
Most people fail at learning to code because they watch, not build. This path is built around making things: every lesson ends with something you type, run and push to GitHub.

## Learning outcomes
- Know the learning loop used in every lesson.
- Know how to get unstuck without giving up or copy-pasting.
- Have a GitHub repo ready for your work.

## Lesson

### The loop
**Read → Type → Build → Commit → Explain.**

- **Read** the lesson once without a keyboard.
- **Type** every example yourself. Typing builds muscle memory and exposes the errors.
- **Build** the matching project in `projects/`.
- **Commit** with a clear message: `lesson 03-02: add tip calculator`.
- **Explain** what you learned in your own words in a `notes/` file. Teaching yourself is the test.

### When you are stuck
1. Read the error message from top to bottom. The real cause is often the first line that mentions your code.
2. Re-read the lesson section that matches the error.
3. Search the exact error text plus `kotlin` or `compose`.
4. After **20 minutes** with no progress, write down the question precisely and ask in a community (links in the resources lesson).
5. Never paste in code you can't explain. If an AI tool helps, ask it to explain, then close it and retype the solution.

### A weekly rhythm that works
- 5 days a week, 1 to 2 hours, rather than one 10-hour day.
- Day 1-2: read and type. Day 3-4: project. Day 5: review and push.

### Set up your notes
Make a `notes/` folder in your own fork. After each lesson write: *3 things I learned, 1 thing I'm unsure about.*

## Practice
Create a GitHub account and a **new empty repository** named `my-android-path`. You'll push your finished projects there as you go.

## Knowledge check
- What are the five steps of the loop?
- What do you do after 20 minutes stuck?
- Why do we type instead of paste?
